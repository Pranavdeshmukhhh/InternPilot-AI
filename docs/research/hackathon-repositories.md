# Hackathon repository source audit

Audit date: **2026-10-21 UTC**. Scope: the three public repositories below, their default-branch source, package manifests and lockfiles, recursive file trees, commit history, release metadata, and available workflow metadata. GitHub read tools supplied the evidence. No repository code, package installation, build, test, scraper, deployment, or provider API request was run. Public source was inspected as untrusted input.

The useful ideas are independent source adapters, a common event model, bounded collection, visible freshness, and deadline-oriented filtering. These repositories do not establish production-ready eligibility checks or a durable reminder system for InternPilot. **Implement independently; no source code was copied into the application.**

### Material limitations

- **Unknown format becomes a fact.** [`normalizer.ts`](https://github.com/reprodev/hackathon-finder/blob/d0ef188a1ce4d6380ee436b03c8d1f7e55293bbc/workers/aggregator/normalizer.ts) returns `virtual` when location is missing. Devfolio and DoraHacks also default missing location to “Online.” These defaults cannot establish India access or remote attendance eligibility.
- **Date precision is invented in some parsers.** MLH/HackerEarth month-and-year fallbacks choose day one. Devfolio's numeric-date heuristic multiplies values below `2_000_000_000_000` by 1000; ordinary 2026 millisecond timestamps also satisfy that condition. Keep explicit timestamp units and date precision instead.
- **Failure can resemble healthy emptiness.** Devfolio/DoraHacks can return `[]` after exhausting failed strategies; other adapters can return `[]` on parse failure. The worker marks a returned fetch as a source success. `healthCheck()` exists in the interface but the aggregation path does not call it. Success, valid empty, partial parse failure and fetch failure need separate results.
- **Refresh triggers lack a handler-level authorization check.** Worker `fetch()` accepts `/__scheduled` and `/trigger` without checking method or credentials. No external gateway protections were audited. InternPilot must use its authenticated controls and durable queue.
- **Aggregation does not verify eligibility.** [`interface.ts`](https://github.com/reprodev/hackathon-finder/blob/d0ef188a1ce4d6380ee436b03c8d1f7e55293bbc/workers/aggregator/adapters/interface.ts) has listing fields, not country/team/academic rules or evidence. The model has start/end dates, not independently named registration and submission deadlines.
- **Merging can retain stale facts or combine the wrong event.** Title/start-date matching lacks stable provider IDs and per-field provenance. Existing end dates are preserved; longer prize text is not necessarily more reliable. Search sorts `prizes` as text, and “active” means end date is null or not past; neither proves registration remains open.
- **Verification is limited.** Ten unit test files are present, but were not run. E2E/integration/property directories contain `.gitkeep` placeholders in this snapshot. The [workflow](https://github.com/reprodev/hackathon-finder/blob/d0ef188a1ce4d6380ee436b03c8d1f7e55293bbc/.github/workflows/deploy-worker.yml) performs deployment without a test step. GitHub returned two historical workflow runs, both failed: [2026-09-06](https://github.com/reprodev/hackathon-finder/actions/runs/34003067557) and [2026-08-27](https://github.com/reprodev/hackathon-finder/actions/runs/33109531109). This is historical workflow evidence, not a determination of current site uptime.

### Material limitations

- **Invented deadlines must never be adopted.** The HackerEarth +14/+30-day fallbacks and using event/submission dates as registration dates violate evidence-backed reminders. Preserve unknowns and separate deadline kinds instead.
- **Failed scrapers can be recorded as successful.** The pipeline catches scraper exceptions, assigns `[]`, updates last-scrape time, completes the log and returns `success: true`. Inserted/updated counters are initialized to zero and never incremented in this function. This undermines monitoring.
- **Static build concerns are visible without running code.** The API route imports `getFilteredHackathons` and `HackathonFilters` from [`src/db/repository.ts`](https://github.com/MArbeeGit/hackathonscraper/blob/c533dd35eb745a367568b9aafec560e416ccfa73/src/db/repository.ts), but that file exports neither. Sort options are parsed/reported without being passed to the filtering call. These are source findings; no build result is claimed.
- **The manual scrape route has no application authorization check.** [`server.ts`](https://github.com/MArbeeGit/hackathonscraper/blob/c533dd35eb745a367568b9aafec560e416ccfa73/src/api/server.ts) installs open CORS and mounts [`/admin/scrape`](https://github.com/MArbeeGit/hackathonscraper/blob/c533dd35eb745a367568b9aafec560e416ccfa73/src/api/routes/admin.ts) without auth middleware; the admin map only includes Devpost. Infrastructure protections were not audited. Actual Express mounts omit the README's `/api` prefix.
- **Unknown attendance is coerced.** [`hackathon.schema.ts`](https://github.com/MArbeeGit/hackathonscraper/blob/c533dd35eb745a367568b9aafec560e416ccfa73/src/schemas/hackathon.schema.ts) defaults unrecognized location to `in-person`; [`status.ts`](https://github.com/MArbeeGit/hackathonscraper/blob/c533dd35eb745a367568b9aafec560e416ccfa73/src/schemas/status.ts) equates a passed registration deadline with a past event and can default invalid dates to upcoming. Registration status and event lifecycle need separate states.
- **Automation is process-local.** There is no durable scheduler lease, persistent retry/dead-letter queue, or reminder/notification delivery implementation in the inspected tree. A log field named `deadLetter` is not a durable dead-letter queue. Four test files exist for schemas, status, deduplication and rate limiting; none were run. No workflow configuration was found.

### Material limitations

- Fetch functions lack `response.ok` checks, timeouts, retry/backoff, runtime response validation and provider rate limiting. Exceptions become `[]` after console logging, making outage versus valid emptiness indistinguishable.
- Fixed six-page batches do not establish complete provider coverage. Results are concatenated without deduplication.
- Dates become locale-dependent display strings and are reparsed for sorting; the sorting code acknowledges date issues and substitutes year 2100 for invalid dates. Unstop `end_date` is displayed while registration `end_regn_dt` is discarded. These are unsuitable inputs for reminder automation.
- Prize sorting strips non-digits and compares numbers across currencies. Unstop sums cash prizes and uses the first currency. Total prize pool is not guaranteed individual compensation.
- The complete tree contains no background worker/cron, database, reminder queue, notification delivery, tests or GitHub workflow configuration. There is no test script in the manifest. Build/test health and current deployment behavior were not verified.

## Recommendations for an independent InternPilot implementation

1. **Extend the existing worker and opportunity model.** Keep `internship` and `hackathon` as explicit kinds, preserving current internship behavior. Start with one or two provider adapters after separately verifying the provider's current access terms and response contract. URLs observed in third-party source are discovery leads, not documented availability or permission guarantees.
2. **Store evidence before making decisions.** Retain provider + stable external ID, canonical/source URL, raw source payload or immutable evidence reference, fetched/last-seen timestamps, extraction version, and per-field provenance. Represent absent location, eligibility, fees, prize and dates as unknown. Distinguish listing claims from organizer-verified rules.
3. **Separate dates and lifecycle states.** Model registration opening/closing, event start/end, and submission deadline independently. Preserve original text, timezone/offset, date precision, and whether the value was explicit or inferred. Never turn an event end into registration close, manufacture a day for a month, or invent now-plus-N dates. Unknown timezone/precision must remain visible and block precise automated reminders when material.
4. **Match only verified facts and applicable rules.** Use the user's verified India residence and 2029 graduation where the event actually states a relevant geographic/academic condition. Online format does not prove worldwide eligibility. Check team size/solo participation, student status, age, region, attendance/travel, fees and availability when mandatory. Explicit incompatibility is ineligible; missing critical evidence requires review. Do not impose an academic restriction on a hackathon whose verified rules explicitly allow everyone.
5. **Make ingestion bounded and observable.** Per-provider enable flags, request deadlines, bounded pages/results, typed runtime validation, rate limits, backoff with jitter, partial-success results, schema-drift alarms and source-specific freshness are useful ideas from these sources. Record valid empty, partial parse, failed fetch and disabled separately; preserve old data during outages and label it stale. Use a durable lease and queue so overlapping schedules or manual runs cannot duplicate work.
6. **Use durable notifications and honest reminders.** Extend InternPilot's existing in-app notification/reminder system with user preferences, deduplication keys, retries and delivery status. Create deadline reminders only from the correct evidenced deadline, and show the original event link. Calendar export and browser countdowns can supplement this; they do not replace scheduled delivery. Registration remains a user action unless separately authorized and safely supported.
7. **Deduplicate cautiously and rank transparently.** Prefer stable source IDs and canonical URLs; use title/date/organizer similarity to propose possible cross-source matches with provenance. Preserve conflicting rules instead of picking longer text. Rank interests, freshness and evidenced deadlines separately from eligibility. Keep prize currency/conditions and distinguish total pool from potential individual awards; never invent stipend or guaranteed winnings.
8. **Validate adapters independently.** Use small saved fixtures for valid/empty/changed/malformed/partial responses, pagination, duplicate IDs, provider outages, Indian eligibility, date-only/timezone boundaries, registration-versus-submission dates and notification idempotency. Provider requests must be read-only and bounded when live verification is later performed. Do not execute these repositories as a shortcut to verification.
